# B-5 指示書：登録者の名前（API・D1）

計画書 `docs/artifacts/plan.md`、決定ログ `docs/artifacts/decisions.md`（AD-16、AD-18）、調査 `docs/artifacts/research/R-1.md` の A を先に読む。
画面は W-2 が同時に作る。下の「API の形」はそちらと約束した形なので変えない（変えたいときは実装せずに報告する）。

## 作るもの

### 1. マイグレーション `migrations/0003_profiles.sql`
- `profiles`：`email`（TEXT、主キー、小文字）、`name`（TEXT NOT NULL）、`source`（`google` か `self`）、`updated_at`（ISO 8601）
- 0001・0002 と同じく、本番で未適用でもデプロイが壊れないこと（`env.DB` が無ければ今までどおり 503）

### 2. API の形（`worker/artifacts.ts`）
- 一覧・1件の各行に `author_name: string | null` を足す（`profiles` を LEFT JOIN）。`author_email` はそのまま残す
- `GET /api/artifacts/me` → `{ ok: true, email, name: string | null }`
  - `profiles` に行があればその name
  - 無ければ Google の名前を取りにいく（下の 3）。取れたら `source: "google"` で保存して返す
  - それでも無ければ `name: null`
- `PUT /api/artifacts/me`、本文 `{ name }` → 前後の空白を除いて 1〜30 字。`source: "self"` で保存（あれば上書き）し、`{ ok: true, email, name }` を返す。不正なら 400 の `{ ok:false, message }`
- `self` の名前は Google の名前で上書きしない

### 3. Google の名前を取る（`worker/access.ts` か新しいファイル）
- `https://<ACCESS_TEAM_DOMAIN>/cdn-cgi/access/get-identity` に、検証済みの JWT（`Cf-Access-Jwt-Assertion` の値）を `Cookie: CF_Authorization=<jwt>` で渡して GET し、JSON の `name` が空でない文字列なら使う（R-1 の参考リンク）
- 失敗・タイムアウト（数秒で打ち切る）・name 無しはすべて null。エラーにしない。ログは warn 1 行
- `ACCESS_DEV_EMAIL` でのローカル開発では呼ばない（null）
- 本物の Access が無いので動作は確かめられない。確かめられないことは PR に書く

### 4. 手順書 `docs/artifacts/setup.md`
- マイグレーションの適用に 0003 を足す。API の一覧に `PUT /api/artifacts/me` と `author_name` を足す

## 触ってよい範囲
`worker/`、`migrations/`、`docs/artifacts/setup.md`。`src/` は触らない（W-2 の担当）。

## 完了条件
- `npm run lint`、`npx tsc --noEmit`、`npm run build` が通る
- ローカル D1（`wrangler dev -c wrangler.local.jsonc`、`ACCESS_DEV_EMAIL` あり）で curl：`GET /me` が `name: null` → `PUT /me` で保存 → `GET /me` と一覧の `author_name` に出る → 不正な名前（空・31 字）が 400。結果を PR に書く
- get-identity を呼ぶ処理は、fetch を差し替えて成功・失敗・name 無しを確かめる（小さなスクリプトでよい。既存にテストの仕組みが無ければ足さなくてよい）
