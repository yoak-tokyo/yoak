# U-1 指示書：画面の方向性のモック

計画書 `docs/artifacts/plan.md` と決定ログ `docs/artifacts/decisions.md` を先に読む。
Yoak の言葉づかいは `verbal-identity.md`、見た目の雰囲気は `src/app/globals.css` と `src/components/` を参考にする。

## 作るもの

PO が見比べて方向性を選ぶための、動くモック（HTML）を 2〜3 案。それぞれ Artifact として公開し、URL を報告する。
リポジトリのファイルは変えない（モックは scratchpad に置く）。

各案に入れる画面：
1. 一覧（カードかリストか、案ごとに変えてよい）。キーワード検索とタグでの絞り込み
2. 登録（claude.ai のリンク、タイトル、説明、タグ）
3. 詳細または編集（本人の登録は編集・削除できる）

案の違いは「一覧の見せ方」と「雰囲気」で出す。例：
- A：カードのギャラリー（サムネ枠あり、ぱっと見て探す）
- B：密度の高いリスト（表に近い。件数が増えても探しやすい）
- C：分類ごとの棚（事業やタグの見出しの下に並ぶ）

ダミーのデータは 10〜15 件。Yoak の事業（Yoak / nightbrew / nomitai / LAMP / CaseMatch）っぽい題材にする。
スマホ幅でも崩れないこと（PO はスマホでも見る）。

## やらないこと
- 機能を増やさない（お気に入り・コメント・通知などは入れない。Q-1 で PO が決める）
- 実装（`src/`）はしない

## 報告
- 各案の URL と、その案の狙い・向いている使われ方を1〜2行ずつ
- あなたが推す案とその理由
