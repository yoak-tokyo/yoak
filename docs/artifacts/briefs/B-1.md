# B-1 指示書：D1 のスキーマと API、Access の JWT 検証

計画書 `docs/artifacts/plan.md`、決定ログ `docs/artifacts/decisions.md`（AD-4、AD-5）を先に読む。

## 作るもの

### 1. 認証（`worker/access.ts`）
- `Cf-Access-Jwt-Assertion` ヘッダーを `jose` で検証する（`createRemoteJWKSet` で `https://<ACCESS_TEAM_DOMAIN>/cdn-cgi/access/certs`、`aud` = `ACCESS_AUD`、`iss` = `https://<ACCESS_TEAM_DOMAIN>`）
- 返すのはログインした人の `email`
- `ACCESS_TEAM_DOMAIN` と `ACCESS_AUD` は `wrangler.jsonc` の `vars`（値は空のプレースホルダ。PO が設定する）
- ローカル開発用：`ACCESS_DEV_EMAIL` が設定されているときだけ、検証をせずにそのメールで通す。本番で効かないよう、`wrangler.jsonc` には書かず `.dev.vars` の例（`.dev.vars.example`）にだけ書く
- JWT が無い・不正なら、ページは 403 の簡素な文、API は 401 の JSON

### 2. ルーティング（`worker/index.ts`）
- `/artifacts`、`/artifacts/*`、`/api/artifacts`、`/api/artifacts/*` は Basic 認証をかけず、Access の検証だけをする（AD-5）
- `/artifacts*` は検証が通れば静的アセットを返す
- `/api/artifacts*` は `worker/artifacts.ts` に渡す
- それ以外の挙動は今のまま変えない

### 3. データ（`migrations/0001_artifacts.sql`、D1 binding 名は `DB`）
- `artifacts`：`id`（TEXT、ランダム）、`url`、`title`、`description`、`author_email`、`created_at`、`updated_at`
- `tags`：`artifact_id`、`name`（多対多。分類の仕方は Q-2 で PO が決めるので、まずは汎用のタグだけにする）
- `url` は `https://claude.ai/` で始まるものだけ受け付ける（Claude のアーティファクトのリンク）。長さの上限も付ける

### 4. API（`worker/artifacts.ts`）
- `GET /api/artifacts?q=&tag=`：一覧（新しい順）。`q` はタイトル・説明の部分一致、`tag` で絞り込み
- `POST /api/artifacts`：登録。`author_email` はログインした人のメールを入れる（本文の値は使わない）
- `GET /api/artifacts/:id`：1件
- `PATCH /api/artifacts/:id`、`DELETE /api/artifacts/:id`：登録した本人だけ（本人以外も許すかは Q-1 で決まる。いまは本人だけにして、判定を1か所の関数にまとめておく）
- `GET /api/artifacts/me`：ログイン中のメールを返す（画面で「自分の登録」を出すため）
- 入力の検証、エラーは `{ ok:false, message }` の JSON。既存の `worker/contact.ts` の書き方に合わせる

### 5. 手順書（`docs/artifacts/setup.md`）
PO が Cloudflare でやる設定を、画面の名前どおりに順番に書く：
- D1 の作成（`npx wrangler d1 create`）と `wrangler.jsonc` への ID 記入、マイグレーションの適用
- Zero Trust の Access Application（self-hosted、`yoak.tokyo/artifacts*` と `yoak.tokyo/api/artifacts*`）、Google ログインの設定、One-time PIN、ポリシー（許可するメールアドレス・ドメイン）
- `ACCESS_TEAM_DOMAIN`・`ACCESS_AUD` の値をどこから取るか
- ローカル開発の仕方（`.dev.vars`、`wrangler d1 migrations apply --local`、`npm run preview`）

## やらないこと
- 画面（`src/`）は作らない。W-1 の担当
- 分類の列（事業・種類など）を勝手に足さない
- Cloudflare の本番の設定や D1 の作成はしない（PO の作業）

## 完了条件
- `npm run lint`、`npx tsc --noEmit`、`npm run build` が通る
- `wrangler dev`（ローカル D1、`ACCESS_DEV_EMAIL` あり）で、登録 → 一覧 → 検索 → タグ絞り込み → 本人の更新・削除 → 他人の更新が 403、を curl で確かめて PR に結果を書く
- `ACCESS_DEV_EMAIL` なしで `/artifacts` と `/api/artifacts` が 403/401 になることも確かめる
- 既存の `/` と `/api/contact` の挙動が変わっていない
