# B-3 指示書：事業の項目を足し、手順書を Google ログインだけに直す

計画書 `docs/artifacts/plan.md`、決定ログ `docs/artifacts/decisions.md`（AD-10、AD-11）、API の現状 `docs/artifacts/setup.md` の「API の一覧」を先に読む。

## 1. 事業の項目（AD-10）
- `migrations/0002_business.sql`：`artifacts` に `business TEXT NOT NULL DEFAULT 'その他'` を足す（既存の行は「その他」）。事業での絞り込み用のインデックスも
- 事業の値は `Yoak` / `nightbrew` / `nomitai` / `LAMP` / `CaseMatch` / `その他` の6つだけ。この一覧は `worker/artifacts.ts` で1か所に定数で持ち、`export` する（画面側は同じ値を自分で持つので、値の綴りを変えないこと）
- `POST /api/artifacts`：`business` は必須。6つ以外は 400
- `PATCH`：`business` を送ったときだけ変える
- `GET /api/artifacts?business=`：事業で絞り込み（`q`・`tag` と組み合わせられる）
- 返す `artifact` に `business` を足す
- `GET /api/artifacts/tags`：使われているタグを、使われている件数の多い順に返す `{ ok, tags: [{ name, count }] }`（画面の「よく使うタグを候補に出す」用。AD-12）。`/api/artifacts/:id` より先に判定し、`tags` という ID と取り違えないこと
- `docs/artifacts/setup.md` の「API の一覧」と「入力の決まり」を更新する

## 2. 手順書を Google ログインだけに（AD-11）
- `docs/artifacts/setup.md` から One-time PIN の手順を消し、Login methods は Google だけにする
- ポリシーは **Emails** で1件ずつ許可する形だけにする（ドメイン単位の例は消す）
- Google の OAuth 同意画面は External のまま（Yoak 外の Google アカウントも入るため）
- `docs/artifacts/decisions.md` は触らない（PM が管理する）

## やらないこと
- 画面（`src/`）は触らない（W-1 が同時に作っている）
- 公開するアドレス（Q-4）は未決。手順書のホスト名は yoak.tokyo のままでよい

## 完了条件
- `npm run lint`、`npx tsc --noEmit`、`npm run build` が通る
- `wrangler dev -c wrangler.local.jsonc`（ローカル D1 に 0001・0002 を当てる）で、business なしの登録が 400、不正な business が 400、正しい登録 → `?business=` の絞り込み → `?business=&tag=&q=` の組み合わせ → PATCH で business の変更 → `/api/artifacts/tags` の件数順、を curl で確かめて PR に書く
- 0001 だけ当てた D1 に 0002 を当てると、既存の行が「その他」になることを確かめる
