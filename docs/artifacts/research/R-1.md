# R-1 調査：登録者の名前と、URL からの自動入力（2026-10-13）

## A. 名前
- Access の JWT（Cf-Access-Jwt-Assertion）には name は入らない（クレームは aud, email, exp, iat, nbf, iss, type, identity_nonce, sub, country）
  https://developers.cloudflare.com/cloudflare-one/access-controls/applications/http-apps/authorization-cookie/application-token/
- `https://<team>.cloudflareaccess.com/cdn-cgi/access/get-identity` に JWT を `Cookie: CF_Authorization=<jwt>` で渡すと、IdP の name が返る例がある（例は Azure AD。Google で入るかは未確認）
  https://developers.cloudflare.com/cloudflare-one/tutorials/extend-sso-with-workers/
  https://developers.cloudflare.com/pages/functions/plugins/cloudflare-access/
- 確かめ方：Access でログインした状態で `https://<workers.dev のホスト>/cdn-cgi/access/get-identity` を開き、name があるか見る
- 代わりの案：本人が初回に表示名を入れる（D1 に「メール → 名前」）、PO が対応表を持つ

## B. URL からの自動入力
- `claude.ai/public/artifacts/{uuid}`：ログインなしで開けるが、サーバーが返す HTML は固定の殻（og:title「Claude Artifact」）。中身は JS が読み込み、Cloudflare のチャレンジで守られている
  https://support.claude.com/en/articles/9547008-share-artifacts
  https://instapods.com/blog/claude-ai-public-artifacts-url/
- `claude.ai/artifact/{id}`・組織内共有：ログインが必要。Worker からは取れない
- → URL から自動で取るのは見込みが薄い
- 代わりの案：登録画面に「中身を貼る」欄を置き、Claude Haiku 5.5 で下書きを作る（1 件 0.1 円以下の見込み。API キー、社内資料を外部 API に送ることの是非、回数制限が要る）。または手順書に「Claude に聞く定型文」を載せる

確かめられなかったこと：Google で get-identity に name が入るか、`claude.ai/artifact/{id}` を匿名で開いたときの HTML、Haiku 5.5 の画像入力。
